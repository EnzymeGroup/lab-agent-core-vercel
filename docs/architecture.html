Architecture

The AI SDK owns the model/tool loop and the message protocol. Core is a thin execution and delivery layer around it: sessions, runs, checks, file boundaries and one loopback HTTP server. Every entry point calls the same streamTurn. Optional tool sets live in a separate package, lab-agent-extras, which Core never imports.

Life of a task turn

  1. Accept

    turn.ts validates the request. gate.ts takes the in-process gate, then the cross-process project lock (store/lock.ts). A second operation gets BusyError (HTTP 409).

  2. Recover and open

    Crash leftovers are marked interrupted (recovery.ts, never replayed). The session is loaded, and its stored tool calls are validated against the current tool schemas.

  3. Freeze

    For a task, runs/store.ts creates runs/<id>/ and provenance.ts hashes the selected inputs, config, scripts, checker files and every available SKILL.md, plus attachments, the tool switches in effect and the host environment.

  4. Stream

    The user message is saved; images and PDFs are kept as project: references and read through the file policy for each model call (attachments.ts). If the model's view would reach the compaction threshold, older turns become session.summary (compact.ts). The project memory index is attached to the latest user message, never stored. ToolLoopAgent.stream() starts with Core's bounded context projection (prompt.ts) inside an ExecutionContext that carries mode, signal, output directory, steering queue and token budget to tools.

  5. Split

    The UI stream is tee()'d. The browser gets a detachable copy; finish.ts consumes the other and saves history at most every 100 ms. Closing the tab never stops accepted work. Only cancel does.

  6. Settle

    When the stream ends, finish.ts waits for in-flight tool executions (tools/guard.ts). A call that needs approval (listed in approval or declaring its own needsApproval, and not switched to always allow) pauses the run as awaiting_approval and releases the lock; respondTurn continues the same message later. Queued steering starts another stream on the same lock.

  7. Record

    Otherwise finish.ts writes the run's terminal execution, its model calls, usage and cost, and hashes the outputs.

  8. Check

    If execution completed, check.ts runs preflight (did inputs or code change?), the checker (argv, no shell, writes AGENT_CHECK_FILE), and a final rehash (did the checker modify files?). The result sets delivery. With repairAttempts, a failed or partial check sends the issues back to the agent and streams again.

  9. Release

    Session state returns to idle and the lock is released. A chat turn has no run: it skips freezing, the run record and the check.

Status model

Two independent fields. Only the checker sets delivery; a model saying "done" is never a passed check.

All records are written through a synced temp file and rename. Metadata paths never traverse symlinks. Unreadable records are reported as issues instead of hiding the rest.

Boundaries

Model file tools

Paths are resolved lexically and through symlinks; both must stay in the project. Secrets, .git, .lab-agent/ and run metadata are hidden. Hard links are refused. Writes need an active task and land in its output/.

Trusted host code

Config, registered Python, MCP servers and native tools run with your permissions and are not sandboxed. Python runs as argv with no shell, in its own process group so cancel stops the whole tree.

Local server

Binds 127.0.0.1 only. Foreign Host/Origin or cross-site fetches get 403. Every API route except bootstrap needs the per-process bearer token.

Outbound requests (extras)

webFetch and citeSource refuse loopback, private, link-local and metadata addresses, checked against the DNS answer actually used, on every redirect. Search and database queries leave the machine.

Model-written commands (extras)

Only shell runs them: bubblewrap with no network, read-only system, empty home, secrets blanked, .lab-agent/ hidden, runs/ read-only. Every call needs approval.

Invariants

  • Full history on disk; only the model's view is bounded. A summary replaces older turns in the view, never in history.
  • A paused approval is not terminal; only the server's own pending calls can be answered.
  • Execution and delivery are separate fields; only a checker sets delivery.
  • Every accepted operation ends with a terminal record, including after a crash.
  • The lock is held until tool processes settle, never released early on abort.
  • Tools and checkers are never replayed after recovery.
  • Model file tools, including search and attachment reads, never see secrets or Core metadata.
  • The config is the ceiling: switches disable tools or skip pauses, never add tools. Helpers never receive tools that need approval.
  • Core never imports extras; extras tools follow the same approval, switch and provenance rules as any tool.
