    ③ 隐形参数：ExecutionContext

    很多东西不出现在工具参数里，比如「这次是哪个 run」「停止信号」「输出目录」。它们放在 Node 的 AsyncLocalStorage 里（workspace/context.ts:50 runWithExecutionContext），沿着 async 调用链自动传下去。所以 readFile 不需要模型告诉它 run id，模型也没法伪造。

    字段谁写入谁读取、用来做什么
    modebeginTurn → executionContext（turn.ts:133）prepareStep 判断 task-only 的 Python 脚本能不能用
    signalbeginTurn 的 AbortController（超时、Stop 按钮）guardTool 合并给每个工具；子进程、检查程序收到后整组杀掉
    runId · outputDirectoryexecutionContext，仅 taskworkspace 写入只许进 runs/<id>/output；extras 的 citeSource、captureEnvironment、submitJob 用它记录归属
    model · modelKeychooseModel 选出的模型prepareStep 每步换上会话选的模型；subagent 默认沿用；记账
    steeringcreateSteeringQueue；steerTurn 往里推prepareStep 注入下一步；finish 决定要不要再跑一段
    clippedboundContext 截断长结果时记下全文readToolOutput 分段读回
    overBudget · onStep · onContextexecutionContextstopWhen 判断 token 预算；记录每次模型调用；上下文用量条
    skillBaselines · onSkillLoadopenRun 的 Skill 指纹loadSkill 核对指纹并标记「用过」

    ④ 推荐读码顺序

    1. agent/create.ts：对外接口长什么样，runTask 和 chat 其实都是 streamTurn + 读完流。
    2. agent/turn.ts：从 streamTurn（319 行）往下读到 beginTurn 和 startModelStream，就是场景 ②。
    3. agent/resources.ts：内核怎么造，6 个钩子各做什么，就是场景 ③ 的前半。
    4. tools/guard.ts → workspace/workspace.ts：每个工具调用都经过的那一层。
    5. agent/finish.ts 的 completeTurn（168 行）：一个 for(;;) 循环管住暂停、插话、返工，就是场景 ④。
    6. runs/check.ts：三段式检查。然后再看 approval.ts、steering.ts、compact.ts 这些单项能力。
    7. 最后看 packages/extras/src/：都是普通的 tool()，只用 Core 的公开接口。
