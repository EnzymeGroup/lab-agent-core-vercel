Agent 框架图（教学版）

一句话：模型 ↔ 工具的循环由 Vercel AI SDK 内核负责；我们写的 Core 是包在外面的 harness，负责排队、准备上下文、在循环里插钩子、事后记账和验收。应用（你的项目）只提供规则、工具、Skill 和检查程序。联网等额外工具放在可选扩展包 packages/extras 里，Core 不依赖它，配置里引入才生效。

Core：我们写的 harnessVercel AI SDK：内核循环应用：项目自己写的入口 / 外部服务磁盘存储Extras：可选扩展包（虚线）

① 总图：入口 → harness → 内核 → 工具 → 存储

读图顺序：上面三个入口 → ① 进入 → ② 准备 → 黄色内核循环（蓝色钩子可以随时介入）→ ③ 收尾 → 写入底部存储，并调用检查程序。

② 一个 turn 怎么跑（从发消息到释放锁）

③ 模型每一步看到什么 vs 磁盘上存了什么

核心原则：硬盘存全量，只裁剪给模型看的那一份。压缩、截断、丢旧轮次都只影响左边，右边永远不动。

④ 模块地图（packages/core/src）

上层只调用下层：cli/ server/ → agent/ → tools/ runs/ → config/ → workspace/ → store/。每一层都能单独读、单独测。

cli/ · server/　入口

  • cli/main.ts 命令表：run、chat、approve、eval、memory…
  • server/routes.ts 本机 HTTP 路由，校验 origin 和 token
  • server/files.ts 上传、预览、下载交付物

agent/　turn 生命周期

  • create.ts 对外接口 createAgent
  • resources.ts 一次性装配工具和内核，挂钩子
  • gate.ts 一次只跑一个操作
  • turn.ts 进入和准备；finish.ts 收尾
  • prompt.ts 系统规则、上下文裁剪

agent/　harness 能力

  • approval.ts 审批　steering.ts 插话
  • compact.ts 压缩成摘要　subagent.ts 子 agent
  • steps.ts 用量和花费　eval.ts 评测
  • recovery.ts 崩溃恢复　mcp.ts 增删 HTTP MCP
  • switches.ts 工具开关（关掉 / 始终允许）
  • attachments.ts 图片、PDF 附件

tools/　给模型的工具

  • index.ts 组装、查重名　guard.ts 取消、输出上限
  • builtin.ts 读写文件、Skill、计划
  • search.ts findFiles、searchFiles
  • memory.ts 记忆工具和目录
  • python.ts · skills.ts · mcp.ts

runs/　任务记录和验收

  • store.ts run.json 读写
  • provenance.ts 冻结输入、算指纹、查改动
  • check.ts 预检 → 检查程序 → 再核对

config/ · workspace/ · store/　底层

  • config/ 读取和校验配置、模型表、计价
  • workspace/ 模型的文件视野、执行上下文、子进程
  • store/ 原子写、项目锁、会话、记忆、工具开关、哈希

应用（你的项目）

  • agent.config.ts 模型、工具、审批、检查程序…
  • AGENTS.md 项目说明　.agents/skills/ 做事方法
  • tools/*.py 注册的 Python 脚本　data/ 输入

apps/workbench　界面

  • Next.js 静态页面，由同一个本地服务提供
  • 会话、对话、审批按钮（含始终允许）、附件、计划、上下文用量条
  • Runs 面板、Capabilities（模型、Skill、记忆、工具开关、MCP）

packages/extras　可选扩展包

  • Core 不依赖它；在 agent.config.ts 里引入才生效
  • web.ts webSearch（Tavily）、webFetch
  • hpc.ts 提交作业立刻返回 jobId，之后再查（Slurm / 本机）
  • bio.ts NCBI、UniProt、Ensembl 只读查询，结果带来源和时间
  • files.ts inspectFile：大文件只读开头，识别 FASTQ / BAM / VCF…
  • env.ts 导出 conda 环境和 pip 包列表，存成 run 产物
  • research.ts deep research：并行 researcher、引用逐字核对、引用检查程序
  • coding.ts editFile / undoEdit、git 只读、bwrap 沙箱 shell（每次都要审批）
  • net.ts 出网请求逐跳检查，拒绝内网地址
  • 测试单独放在 tests/extras/

谁负责例子

⑥ 关键规则（整个框架守住的几条线）

  1. 硬盘存全量，只裁剪给模型看的那一份。摘要、截断、丢旧轮次从不改写历史。
  2. 执行完成 ≠ 结果合格。run 的执行状态和交付结果分开记；只有检查程序能判定合格。
  3. 每个被接受的操作都有终态记录，进程崩溃后也会补上（标记为中断）。
  4. 工具进程彻底停下之前不放锁，点停止也一样。
  5. 崩溃恢复从不重放工具。审批暂停不算崩溃，恢复时不动它；客户端只能答复服务端自己记录的待审批调用。
  6. 模型的文件工具（包括搜索和附件读取）看不到密钥和 .lab-agent/；记忆只能通过记忆工具访问。
  7. 配置是上限。工具开关只能关掉已有工具，或让需要审批的工具“始终允许”，不能凭空加工具；每个任务都记下当时的开关。需要审批的工具有两种来源：写在配置 approval 里的，和工具自己声明 needsApproval 的；helper 永远拿不到这类工具。
  8. 扩展包可选，Core 不依赖它。webFetch 默认拒绝内网和云元数据地址，网页内容只当数据，不当指令。唯一会执行模型所写命令的是 coding 的 shell：跑在 bwrap 沙箱里，每次调用都要人审批。
  9. 只跑可信的本地代码。注册的 Python 和 MCP 没有沙箱，用的是本机权限；服务只监听 127.0.0.1。
  10. 没有自建模型循环、没有第二套消息格式、没有工作流调度器。编排靠钩子、子 agent 和多段 turn 完成。
